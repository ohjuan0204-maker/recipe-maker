# 배포 프롬프트 — 대회 컴퓨터의 랄프톤 폴더를 공개 사이트로

이 파일과 `deploy/spec.md`를 대회 컴퓨터의 **랄프톤 폴더** 안 `deploy/` 폴더에 둔다. Claude Code도 랄프톤 폴더에서 연다.
Claude Code는 컴퓨터의 파일을 고치고 GitHub에 푸시하는 데까지 한다. 저장소 만들기, GitHub 로그인, Pages 켜기는 사람(또는 사람이 로그인해 둔 `gh`)만 할 수 있고, 이 셋이 없으면 사이트가 생기지 않는다.
대회 규칙 ②(가재탈): 런 중에 노트북을 만지면 가재탈·운영요원·[양식4] 기록이 필요하다. 그래서 노트북을 만지는 준비는 **Phase 1(19:10~19:50)에 모두 끝낸다.**

## 출발 전 (사람) — Phase 1(19:50 전)에 끝낸다

1. `deploy/spec.md` 0장 표를 채운다: GitHub 아이디, 저장소 이름(`recipe-maker`, 영문), 커밋 이름·메일(noreply 메일 권장), Public 여부와 선생님 확인 여부, 첫 배포 마감(20:30)과 최종 마감(21:00), **체험 완료 코드(빈칸·`미정` 금지)**, 런 중 휴대폰으로 GitHub 설정을 바꿔도 되는지(운영요원 확인).
   - 아이디 칸이 비어 있으면 붙여 넣지 않는다.
   - Public에 `아니오`면 붙여 넣지 말고 바로 계획 B(spec 6장)로 간다.
   - 체험 완료 코드는 체험 투표(25점)에 쓰인다. 운영진이 정해 준 코드가 있는지 지금 묻는다.
2. Git 설치 확인: 터미널에서 `git --version`.
   - 없으면 `winget install --id Git.Git -e --source winget`(또는 git-scm.com에서 받아 기본값으로 설치). "Git Credential Manager"는 기본값으로 켜져 있다.
3. GitHub CLI 설치와 로그인(런 중 로그인 창이 뜨지 않게 하는 핵심):
   - `gh --version`. 없으면 `winget install --id GitHub.cli -e --source winget`.
   - **터미널을 새로 열고** `gh auth login` → GitHub.com → HTTPS → "Login with a web browser" → 화면의 코드를 브라우저에 넣고 Authorize.
   - `gh auth setup-git` (이후 `git push`가 로그인을 묻지 않는다).
   - `git config --global user.name "0장 이름"`, `git config --global user.email "0장 메일"`.
   - `gh`를 끝내 못 깔면: 첫 푸시 때 로그인 창이 뜨므로, 첫 푸시는 런 밖(중간 점검 20:20~20:30)에 하거나 가재탈로 처리한다.
4. 빈 저장소 만들기(휴대폰으로 해도 된다): github.com/new → Owner: 내 아이디, Repository name `recipe-maker`, **Public**, "Add a README file"·".gitignore"·"license"는 **모두 끈다** → Create repository.
   - 또는 3번을 끝냈으면 터미널에서 `gh repo create recipe-maker --public` (폴더를 올리지는 않는다. 올리는 것은 에이전트가 한다).
5. 랄프톤 폴더에서 Claude Code를 연다(지금 켜 둔 세션이 다른 폴더에 있으면 새로 연다. 1차 때 세션이 폴더를 옮기면서 워크플로가 꺼졌다).
   - 터미널·Claude를 Git·gh 설치 **뒤에** 새로 연 것이어야 `git`, `gh`가 보인다.
6. 아래 둘 중 하나로 넣는다.
   - **권장 — 1차 런(19:50)에 함께:** 1차 프롬프트의 맨 앞에 이 한 줄을 붙인다.
     `먼저 deploy/prompt.md의 [배포 프롬프트] 1)~8)을 한다(첫 배포, 공개 주소 반영 확인). Pages 반영을 기다리는 동안 아래 1차 작업을 하고, 1차 작업이 끝나면 9)~13)을 한다.`
   - 또는 따로: 아래 **[배포 프롬프트]** 전체를 붙여 넣는다. 이때 `/goal`은
     `deploy/spec.md 8장 끝의 기준을 만족한다(공개 주소에서 check_pages.mjs가 같음 n/n, 데모 1~8단계 통과, 체험 완료 코드가 보임) 또는 6장 계획 B로 멈춘다`
7. 런 중 에이전트가 부르면(되도록 0번):
   - "로그인 창이 떴습니다" → 가재탈, 운영요원에게 알림, 로그인, [양식4] 기록.
   - "Pages를 켜 주세요" → 0장 운영요원 확인이 `예`면 휴대폰으로 저장소 Settings → Pages → Source "Deploy from a branch" → `main`, `/ (root)` → Save(노트북을 만지지 않는다). 아니면 중간 점검 때 한다.
   - "이 파일을 커밋해도 되나요" → 학생 이름·학번이 든 문서면 "아니오"(이 대답도 노트북을 만지면 가재탈).

## 중간 점검 (20:20~20:30, 사람)

- 휴대폰으로 공개 주소를 연다. **모바일 데이터와 학교 와이파이 둘 다.** 홈, [샘플: 총괄성 실험], [1분 체험] 1~2단계.
- 안 떴으면 spec 5장 표로 원인을 찾아 FIX 로그에 "실패한 것 → 명세·프롬프트를 어떻게 고쳤는지"를 적고, SPEC·PROMPT(2차 프롬프트)를 고친다. 코드는 고치지 않는다. Pages가 꺼져 있으면 이때 켠다.
- `loop2/spec.md` 0장의 공개 주소 칸이 채워졌는지 본다. 채워졌으면 2차 런(20:30)은 `/goal` A, 공개 주소가 아직 안 뜨면 `/goal` B로 간다.

## 반드시 지킬 것
- 앱 코드를 바꾸지 않는다. 예외 1: 참조 경로의 대소문자를 실제 파일 이름에 맞추기. 예외 2: 체험 완료 코드가 빈칸·미정이면 0장 코드로.
  예외를 쓸 때도 node --test 전체 통과를 확인하고 진행 로그에 이유를 적는다.
- 비밀번호·토큰·인증 코드를 묻거나, 입력하거나, 파일에 적지 않는다. 로그인 창이 뜨면 "런 중이면 가재탈"이라고 사람에게 알리고 기다린다.
- 사람을 부르는 일을 최소로 한다(가재탈 룰). gh가 로그인돼 있으면 Pages 켜기와 반영 확인은 gh로 직접 한다.
- 강제 푸시(--force), 이미 푸시한 커밋 고치기, 저장소 지우기·이름 바꾸기·공개 범위 바꾸기를 하지 않는다.
- 학생 이름·학번이 들어 있을 수 있는 문서(.hwp/.hwpx/.pdf/.docx/.xlsx 등, tests/fixtures 밖)와 API 키처럼 보이는 글자는 커밋하지 않고 사람에게 묻는다(규칙 ⑤).
- 외부 라이브러리·패키지를 설치하지 않는다. 확인 도구(tools/check_pages.mjs)는 Node 기본 기능(fetch, crypto, fs, child_process)만 쓴다. gh가 없으면 설치하지 않는다.
- 브라우저 인쇄 창을 띄우지 않는다. 라벨은 화면 미리보기까지만.
- 작업 폴더를 옮기지 않는다. 이 랄프톤 폴더에서 끝까지 한다. 경로에 한글이 있으면 명령에서 따옴표로 감싼다.
- 공개 주소에 같은 요청을 1분보다 짧은 간격으로 되풀이하지 않는다.
- 모든 결과는 실제 명령 출력으로 진행 로그 "배포" 절에, 실패와 고친 방법은 FIX 로그에 적는다(규칙 ⑥).
- 0장의 최종 마감(21:00)이 지나면 그 자리에서 6장 계획 B로 멈춘다.
