   1. `git --version` (1차 때 이 노트북에는 Git이 없었다. 설치했으면 터미널을 새로 연다)
   2. `git config --global user.name "이름"`, `git config --global user.email "메일"` (없으면 커밋이 안 된다)
   3. GitHub에서 **Public** 저장소를 만든다(README·.gitignore 없이). 무료 계정은 Private 저장소로는 Pages를 켤 수 없다. 공개하면 `reagents.js`의 학교 시약 목록도 공개되니, 선생님 확인이 아직이면 함께 확인한다.
   4. 이 폴더에서 `git init -b main` → `git add -A` → `git commit -m "1차 루프 끝 상태"` → `git remote add origin https://github.com/<아이디>/<저장소>.git` → `git push -u origin main`. 처음 뜨는 GitHub 로그인 창은 사람이 끝낸다.

   6. 저장소 Settings → Pages → Source "Deploy from a branch", Branch `main`, `/ (root)` → Save.
   7. 1~3분 뒤 Actions 탭의 pages-build-deployment가 초록인지 보고, **시크릿 창**에서 `https://<아이디>.github.io/<저장소>/`를 연다. 첫 화면에 "용액 레시피 메이커"가 보이고 [샘플: 총괄성 실험]을 누르면 고체 조제 표가 채워지면 통과. 주소와 시각을 0장에 적는다.

4. 대회 컴퓨터의 랄프톤 폴더에서 Claude를 연다. 이미 켜 둔 세션이 다른 폴더에 있으면 새 세션을 이 폴더에서 시작한다. 1차 때는 세션이 도중에 폴더를 옮기면서 첫 워크플로가 꺼졌다.

## 작업 방식 (ultracode 워크플로)
파일이 겹치지 않게 레인을 나눠 병렬로 진행하고, 합치는 것은 메인이 순서대로 한다.
레인마다 "이 일을 하지 않은 검증 에이전트"를 붙여 Python으로 다시 계산하고 반박을 시도하게 한다.

  F19·F22는 실험별 예시값을 돌려주는 데이터·함수까지만 하고 화면 연결은 메인에 넘긴다. calc.js는 건드리지 않는다.
- 레인 B(실험 내용): experiments.js — F20에 필요한 실험별 기호 데이터(K_sp, σ) → F21(색 이름)
- 레인 C(샘플): calc.js의 SAMPLE과 흡광도 샘플 데이터 — F02·F05의 계산 쪽. calc.js를 고치는 레인은 C 하나뿐이다.
- app.js·index.html·style.css를 고치는 일은 레인에서 하지 말고 메인이 레인이 끝난 뒤 이 순서로 한다(spec 2-1장과 같다):
  F02·F05(버튼, 1분 체험) → F20(홈 '오늘의 실험' 카드 포함) → F26 → F16 → F24·F23·F17 확인(레인 A 결과를 화면에서) →
  F19·F22 화면 연결 → F21(레인 B 결과를 화면에서) → F25 → F18.
- 이미 있는 파일은 Write로 통째로 덮어쓰지 않고 Edit으로만 고친다. 테스트 파일은 레인마다 따로 쓴다:
  레인 A tests/fixplan_EA.part.js, 레인 B tests/fixplan_EB.part.js, 레인 C tests/fixplan_EC.part.js, 메인 tests/fixplan_EM.part.js.
  tests/fixplan.test.js에 불러오는 줄을 넣는 것은 메인만 한다(.part.js는 node --test가 따로 줍지 않는다).

1) 완료 조건을 테스트로 먼저 쓰고 실패를 확인한다(번호는 F16 → A127 … F26 → A137, F05 → A116).
